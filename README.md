# 목회 비서 (ministry-secretary) v0.2

아동부·청년부를 한 사람이 관리하는 웹앱입니다. 화면은 **빌드 없는 정적 사이트**(HTML·CSS·JavaScript)이고, 선택 기능으로 **로그인과 사용자별 저장**(Cloudflare Pages Functions + D1)을 켤 수 있습니다.

| 모드 | 언제 | 데이터 저장 |
|---|---|---|
| **로컬 모드** (기본) | 서버를 설정하지 않았을 때 | 쓰는 브라우저(기기)에만 저장. 서버로 전송하지 않음 |
| **로그인 모드** | 아래 ‘로그인 켜기’를 마쳤을 때 | 계정마다 서버(D1)에 따로 저장. 같은 사이트를 써도 서로 보이지 않음 |

- 메뉴(왼쪽): 홈 · 일정·계획 · 행사 · 예배 · 인원·출석 · 회계 · 설정 (+ 도움말)
- 처음 열면 가상 데이터가 들어 있어 모든 기능을 눌러볼 수 있습니다(로그인 모드의 새 계정은 빈 상태로 시작).
- 보호자 연락처·알레르기·계좌·주민번호는 **입력받지 않습니다**.

## 사용을 돕는 장치
- **처음 시작하기 체크리스트**(홈): 인원 → 연간 계획 → 행사 → 예배 → 출석 → 예산 → 백업. 데이터에서 자동으로 완료 표시됩니다.
- **화면별 사용법 카드**와 **도움말**(왼쪽 아래): 처음 시작하기 / 용어 설명(신청·참석, 예산 잔액·수입·지출 차액 등) / 자주 묻는 질문.
- **예시(템플릿)**: 행사(여름성경학교·수련회·성탄 발표회·소풍·일반) — 행사 시작일 기준 마감일이 계산된 준비 업무와 준비물을 만들어 줍니다. 월별 교육 주제 예시, 절기 예시(사순절~성탄절, 해당 연도 날짜 계산), 예배 순서 예시(어린이·청년·특별), 예산 항목 이름 추천.
- **빈 화면 안내**와 입력칸 설명, **CSV 내보내기**(출석부·명단·거래), **백업 알림**(30일 넘게 내보내지 않으면 홈에 안내).
- 예시는 모두 출발점입니다. 성경 본문은 장·절 참조만 있고 ‘확인 필요’ 표시가 붙어 있으니 개역개정 본문을 확인하세요. 교회마다 날짜가 다른 절기(어린이주일·추수감사절)는 직접 수정하세요.

## 디자인
- **분위기(색·글자·여백)**: `DESIGN-notion.md` 가이드 — 따뜻한 종이색 배경(`#f6f5f4`), 흰 카드와 얇은 테두리, 구조에 쓰는 강조색은 파란색 `#0075de` 하나, 굵은 제목, 입력칸 4px·카드 12px·주요 버튼 알약형. 분류 색(아동부 청록, 청년부 보라)은 배지에만 씁니다.
- **구성(대시보드·메뉴·표·버튼)**: Tabler(MIT 라이선스)의 요약 카드 행, 카드 머리글+목록/표 조합, 세로 사이드 메뉴(활성 항목 파란 표시), 진행 막대, 상태 배지를 **참고해 직접 작성**했습니다. Tabler의 코드·아이콘·CSS는 가져오지 않았습니다.
- **홈**: 요약 카드 4개(이번 주 일정 / 준비할 일 / 이번 달 지출 / 예산 잔액) → 이번 주 일정과 준비할 일(마감 D-day 배지) → 예산 현황 → (미완료 시) 시작 체크리스트.
- **출석**: 출석 체크는 왼쪽 이름(동그란 이니셜+반), 오른쪽 큰 ‘출석 체크 / ✓ 출석’ 버튼. 출석부 표는 이름 칸 고정, 파란 ✓ / 주황 ✕ / 점(미기록), 출석률 막대, 이번 날짜 강조.
- **회계**: 예산 → 지출 → **예산 잔액**(강조) → 수입 → 수입·지출 차액이 한 줄, 항목별 표에 집행률 막대와 ‘초과’ 배지.
- 글꼴: Inter 파일은 포함하지 않았습니다(PC에 있으면 사용, 없으면 맑은 고딕 등 시스템 글꼴).
- 이전 Notion 스타일 파일은 `design/`에 보관했습니다(배포 안 됨).

- **부서 색**: 아동부 노랑 · 청년부 파랑 · 전체 초록(진한 초록). 부서를 고르면 메뉴·버튼·맨 위 줄·카드 강조·부서 배지 색이 함께 바뀝니다. 색은 `public/style.css` 맨 위 `--kid` `--yth` `--all` 값만 고치면 됩니다.
- **이미지**: 기본 그림(로고, 로그인 그림, 빈 화면 6종)은 `public/img/*.svg`로 직접 만들어 들어 있습니다. AI로 만든 이미지로 바꾸는 방법과 프롬프트는 [docs/이미지-프롬프트.md](docs/이미지-프롬프트.md), 교체는 `public/img/manifest.json`에서 합니다.
- **예배와 일정은 따로**: ‘예배’ 메뉴는 주일예배 등 예배와 출석, ‘일정·계획’은 교사 기도회·교사 회의·교사 연수 같은 모임과 행사를 모읍니다. 달력에서 ‘예배도 함께 보기’를 켜면 예배도 같이 보입니다.
- **반복 입력**: 예배·일정을 만들 때 ‘반복’(매주/격주/매월 같은 날짜/매월 같은 요일·주차)과 ‘반복 종료일’을 고르면 한 번에 여러 개가 만들어집니다(최대 104회, 같은 이름·날짜가 있으면 건너뜀). 반복으로 만든 것은 ‘이 날짜부터 반복 전체 삭제’로 한 번에 지울 수 있습니다.
- **교회력(절기) 자동 표시**: 날짜만으로 ‘대림절 제1주’, ‘성탄절(성탄일)’, ‘사순절 제3주’, ‘부활절(부활주일)’, ‘성령강림 후 제N주’ 등을 계산해 예배 목록·달력(주일)·입력 화면에 보여 줍니다(전례 색 포함). 어린이주일·어버이주일·맥추감사주일·추수감사주일 등 한국 교회 주일도 함께 표시합니다. 서방 교회력의 일반 규칙이라 교단·교회마다 이름과 주차 세는 방법이 다를 수 있으니 확인해서 쓰세요. ‘연간·절기 계획’ 탭에서는 올해 교회력 표를 보여 주고, 절기 계획이 비어 있으면 기본 절기를 자동으로 채웁니다.
- **명단 한꺼번에 등록**: 인원·출석 → 명단 → ‘등록 양식 내려받기’로 엑셀 양식(CSV)을 받아 입력하고 올리면 미리보기(등록·중복·오류 줄)를 보여 준 뒤 한 번에 등록합니다. 엑셀에서 표를 복사해 붙여넣어도 됩니다. 한 번에 500명까지, 이미 있는 사람(같은 이름·부서·반·출생년도)은 건너뜁니다. 엑셀 기본 ‘CSV’(한글 윈도우 CP949)도 읽습니다.
- **영수증 사진**: 지출·수입을 등록할 때 사진을 붙일 수 있습니다(휴대폰은 바로 촬영). 사진은 올리기 전에 브라우저에서 작게 줄이며 위치 정보 등 숨은 정보는 지워집니다. 로그인 모드에서는 서버(D1 `receipts` 표, 처음 사용할 때 자동 생성)에 **내 계정으로만** 저장되고(한 장 400KB, 계정당 300장·60MB), 로그인 전에는 이 브라우저에만 저장됩니다(약 2MB). **사진은 백업 파일(JSON)에 들어가지 않으니** 종이 영수증도 보관하세요. 카드번호·주민번호·실명은 가리고 찍으세요.
- **로그인 화면**: 왼쪽 소개 + 오른쪽 입력 화면. 로그인 서버를 켜기 전에도 `설정 → 로그인 화면 미리보기`(또는 주소 끝에 `#login-preview`)로 모양을 볼 수 있습니다.
## 폴더 구조
```
public/              ← 배포되는 화면 (Cloudflare Pages 출력 폴더)
  index.html  style.css  _headers  _routes.json
  js/app.js          화면
  js/store.js        데이터·집계 로직 (브라우저와 서버 검증에서 공통 사용)
  js/templates.js    예시·도움말 내용
  js/auth.js         로그인 화면, 서버 저장 연결
  js/csv.js  js/seed.js  js/images.js
  img/              기본 그림(.svg)과 교체용 manifest.json
functions/           ← 로그인·저장 API (Cloudflare Pages Functions)
  api/[[route]].js   /api/* 진입점
  _lib/handler.js    가입·로그인·세션·저장·계정 삭제
migrations/0001_init.sql   D1 테이블 만들기 SQL
scripts/             로컬 미리보기 서버(serve.js, dev-api.js)
tests/               자동 테스트
design/              이전 디자인(Notion 스타일) 보관 — 배포 안 됨
```

## 내 PC에서 확인하기
Node.js 20 이상이 필요합니다(없으면 `winget install OpenJS.NodeJS.LTS`). 설치할 패키지는 없습니다.
```bash
npm test
npm start
npm run dev:api
```
- `npm start` → `http://localhost:8788` : 로컬 모드(정적 미리보기)
- `npm run dev:api` → `http://localhost:8789` : **로그인 포함** 전체 동작(진짜 SQL 데이터베이스를 SQLite 파일로 대신 사용, 초대 코드 `dev-invite-local-only`, 데이터는 `.devdata/`에 저장되며 GitHub에 올라가지 않음)

## 1. GitHub에 올리기 전 검토하는 방법
이 폴더의 변경 사항은 **GitHub에 올라가 있지 않습니다.** `main`에 바로 올리지 말고 **작업 브랜치 → Pull Request → 검토 → 병합** 순서를 쓰면, 병합 전에는 실제 사이트가 바뀌지 않습니다.

> ⚠️ **파일을 일부만 올리면 사이트가 깨집니다.** (예: `index.html`만 새 것이고 `style.css`가 예전 것이면 메뉴가 세로로 쌓입니다.) 아래처럼 **폴더 째로** 올리세요.

**브라우저만으로 올리기 (Git 설치 불필요)**
1. GitHub 저장소 → **Add file → Upload files**
2. 탐색기에서 `C:\Users\User\ministry-secretary`를 열고 아래 항목을 **한꺼번에 끌어다 놓기**: `public`, `functions`, `migrations`, `scripts`, `tests`, `design`, `README.md`, `package.json`, `.gitignore`
   - 올리면 안 되는 것: `.claude`, `.devdata`, `node_modules` 폴더
3. 올릴 파일 목록을 눈으로 확인(실제 이름·연락처 파일이 없는지) → **Create a new branch for this commit and start a pull request** 선택 → Commit
4. PR의 **Files changed**를 검토하고 문제없으면 **Merge**. (Cloudflare를 연결해 두었다면 PR마다 미리보기 주소가 생깁니다.)

**Git을 쓴다면**: `winget install --id Git.Git -e` 후
```bash
git clone https://github.com/<내 아이디>/ministry-secretary.git
git checkout -b feat/update
git add -A
git diff --cached
git commit -m "목회 비서 업데이트"
git push -u origin feat/update
```

## 2. Cloudflare Pages 설정
Workers & Pages → Create → **Pages → Connect to Git**(화면에 ‘Continue to Pages’ 링크가 보이면 그것을 선택) → `ministry-secretary` 선택.

| 항목 | 값 |
|---|---|
| 프로덕션 브랜치 | `main` |
| 프레임워크 프리셋 | None |
| 빌드 명령어 | `exit 0` |
| 빌드 출력 디렉터리 | `public` |
| 루트 디렉터리 | 비움 |

저장소 루트의 `functions/` 폴더가 있으면 Cloudflare가 자동으로 서버 코드(Functions)로 배포합니다.

## 3. 로그인 켜기 (사용자별 저장)
**로그인 없이도 사이트는 동작합니다(로컬 모드).** 사용자마다 따로 쓰게 하려면 한 번만 아래를 설정하세요. 대시보드 메뉴 이름은 바뀔 수 있으니 비슷한 이름을 찾으세요.

1. **D1 데이터베이스 만들기**: Cloudflare 대시보드 → Storage & databases(또는 Workers & Pages) → **D1** → Create database → 이름 `ministry-secretary-db`
2. **테이블 만들기**: 만든 데이터베이스 → **Console** → `migrations/0001_init.sql` 파일 내용 전체를 붙여넣고 실행
3. **Pages 프로젝트에 연결**: Workers & Pages → 프로젝트 → **Settings → Bindings → Add → D1 database** → Variable name을 **`DB`**(대문자 그대로)로 입력 → 위 데이터베이스 선택
4. **초대 코드 정하기**: **Settings → Variables and Secrets → Add** → 이름 **`INVITE_CODE`**, 값은 **12자 이상**의 길고 추측하기 어려운 문장(짧으면 가입이 자동으로 닫힘), **Encrypt(비밀)** 체크 → Save. 이 코드를 아는 사람만 가입할 수 있습니다. (설정하지 않으면 가입이 닫혀 있습니다.) 혼자 쓴다면 같은 화면에서 **MAX_USERS** = 1도 추가하고, **내 계정을 만든 뒤에는 INVITE_CODE를 삭제**해 가입을 완전히 닫으세요. 자세한 점검 결과와 설정은 [SECURITY.md](SECURITY.md)를 보세요.
5. **다시 배포**: Deployments에서 최신 배포를 다시 실행(Retry) — 바인딩과 변수는 다음 배포부터 적용됩니다. 프로덕션 환경에 설정했는지 확인하세요(미리보기 환경은 따로 설정).
6. 사이트를 열면 **로그인·가입 화면**이 나옵니다. 가입 탭에서 이메일·비밀번호(10자 이상)·초대 코드를 입력하세요.

### 로그인 확인 방법
- 가입 후 왼쪽 아래에 이름과 ‘● 저장됨’이 보이면 서버 저장 연결 성공
- 새로고침·로그아웃·다시 로그인해도 데이터가 남아 있는지 확인
- 다른 브라우저(또는 시크릿 창)에서 **다른 이메일로 가입**해 서로의 데이터가 보이지 않는지 확인
- 같은 계정으로 두 곳에서 동시에 고치면 ‘다른 기기에서 먼저 저장했어요’ 창에서 어느 쪽을 쓸지 고릅니다

### 관리자 작업 (D1 Console에서 SQL 실행)
- 사용자 목록: `SELECT email, name, datetime(created_at/1000,'unixepoch') FROM users;`
- 사용자 삭제(그 사람의 데이터도 삭제): 
  ```sql
  DELETE FROM sessions WHERE user_id=(SELECT id FROM users WHERE email='사람@메일');
  DELETE FROM user_state WHERE user_id=(SELECT id FROM users WHERE email='사람@메일');
  DELETE FROM users WHERE email='사람@메일';
  ```
- 비밀번호를 잊은 사용자: 자동 재설정이 없으므로 위로 삭제한 뒤 다시 가입(데이터는 사용자가 미리 ‘내보내기’한 파일로 복원)
- 초대 코드 바꾸기: Variables and Secrets에서 `INVITE_CODE` 수정 후 재배포(이미 가입한 사람은 영향 없음)

## 4. 배포된 사이트 확인
1. Deployments가 Success인지 확인하고 `https://<프로젝트 이름>.pages.dev`를 엽니다.
2. 메뉴 7개, 출석 체크, 지출 등록(금액 0은 거부), 새로고침 후 유지, 휴대폰 화면을 확인합니다.
3. F12 → Network → 첫 요청의 Response Headers에 `Content-Security-Policy`, `X-Frame-Options`가 있는지 확인합니다.
4. 404 → 출력 디렉터리가 `public`인지 / 메뉴가 세로로 쌓임·옛 디자인 → 일부 파일만 올라갔는지 / 로그인 화면이 안 나옴 → 로컬 모드(3장 미설정) 또는 강력 새로고침(Ctrl+F5)

## 5. 보안·개인정보와 한계 (꼭 읽어 주세요)
**로그인 모드에서**
- 비밀번호는 원문 저장 없이 PBKDF2-SHA256(소금 포함)으로 해시합니다. 세션은 HttpOnly·Secure·SameSite=Strict 쿠키이고, 서버에는 토큰의 해시만 저장합니다(14일). 화면은 30분 동안 아무 조작이 없으면 자동 로그아웃합니다.
- 로그인·가입 시도는 횟수를 제한합니다(이메일당 15분에 8회, 접속 주소당 30회, 잘못된 초대 코드는 전체 30회/시간). 비밀번호는 10자 이상이며 너무 흔한 것·이메일이 들어간 것은 거부합니다. 다른 출처의 요청은 거부하고, 서버 오류 내용은 화면에 보이지 않습니다.
- 각 요청은 **로그인한 본인의 데이터만** 읽고 씁니다(사용자 번호를 요청으로 받지 않음).
- **한계**: ① 비밀번호 해시 반복 횟수가 100,000회로, 최신 권장치(OWASP 600,000회)보다 낮습니다(Workers의 WebCrypto 제한을 고려한 값 — 긴 비밀번호 10자+와 시도 제한으로 보완). ② 이메일 인증·비밀번호 자동 재설정·2단계 인증이 없습니다. ③ 데이터는 암호화 없이 D1에 JSON으로 저장되므로 **사이트 관리자는 기술적으로 모든 사용자의 데이터를 볼 수 있습니다.** 아이들 이름을 입력하는 것에 대해 교회의 개인정보 방침과 보호자 안내를 먼저 확인하세요. ④ 사용자 한 명의 데이터는 한 덩어리(약 1.5MB까지)로 저장되어, 몇 년 치 출석이 쌓이면 한계에 닿을 수 있습니다(넘으면 저장되지 않고 ‘데이터가 너무 커요’ 안내가 나오니, 그때 ‘내보내기’ 후 오래된 기록을 정리하세요). ⑤ 초대 코드는 모두가 공유하는 비밀이라, 유출되면 코드를 바꾸세요.
- 사이트 접근 자체를 막으려면 Cloudflare Access 같은 별도 접근 제어를 함께 검토하세요(이 저장소에서는 설정하지 않았습니다).

**로컬 모드에서**: 데이터는 각자의 브라우저에만 있고 기기 간 공유되지 않습니다. 설정의 ‘내보내기(JSON)’로 백업하세요.
